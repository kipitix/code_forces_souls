# E. Хроностаз

## Условие

Дан скрытый массив `a` из `n` строго положительных целых чисел. Из него получают
массив `b`:

- `b1 = a1`
- `bi = ai - ai-1` для `i = 2..n`

Массив `b` затем перемешивают. По перемешанному `b` нужно восстановить
лексикографически наименьший массив `a` из строго положительных целых чисел,
либо вывести `-1`, если это невозможно ни при какой перестановке.

## Ключевое наблюдение

### Как устроена задача "в лоб"

По условию у нас есть `n` значений (мультимножество `b`), и мы должны:

1. Выбрать, какое из этих `n` значений играет роль `a1` (его записываем в `a`
   без изменений).
2. Оставшиеся `n-1` значений расставить по ролям `d2, d3, …, dn` — то есть
   решить, в каком порядке их подставлять как разности `ai - ai-1`.

Формулы восстановления при этом такие:

```
a1 = <выбранное значение для роли a1>
a2 = a1 + d2
a3 = a2 + d3 = a1 + d2 + d3
a4 = a3 + d4 = a1 + d2 + d3 + d4
...
ai = a1 + d2 + d3 + … + di
```

То есть на первый взгляд кажется, что задача состоит из двух разных частей:
"особый" выбор `a1` отдельно, и отдельно — перестановка оставшихся `n-1`
значений как разностей. Это выглядит сложнее, чем просто "переставить весь
массив".

### Почему это на самом деле одно и то же

Присмотримся к формуле для `ai` внимательнее:

```
ai = a1 + d2 + d3 + … + di
```

Это сумма `i` слагаемых: одно значение, сыгравшее роль `a1`, и `(i-1)`
значений, сыгравших роль разностей `d2..di`. А теперь заметим: если мы
пронумеруем **все** `n` использованных значений (и то, что стало `a1`, и все
`di`) в том порядке, в котором они "вступают в игру" — то есть

```
c1 = a1              (роль a1)
c2 = d2               (роль первой разности)
c3 = d3               (роль второй разности)
...
cn = dn
```

— то `(c1, c2, …, cn)` — это просто некоторая перестановка **всего**
мультимножества `b` (каждое значение `b` использовано ровно один раз: одно —
как `c1`, остальные — как `c2..cn`). И формула для `ai` переписывается как

```
ai = c1 + c2 + … + ci
```

Это в точности определение префиксной суммы перестановки `(c1,…,cn)`! Причём
работает это и для `i = 1`: `a1 = c1` — это префиксная сумма из одного
слагаемого, никакого особого случая тут нет. То есть "особая роль `a1`" — это
не отдельное правило, а просто частный случай общей формулы префиксной суммы
при `i=1`. Разделение на "выбор `a1`" и "расстановка разностей" было мнимым:
оба шага — это на самом деле один и тот же шаг "выбрать порядок всех `n`
элементов `b` и посчитать её префиксные суммы".

### Числовой пример

Возьмём пример из условия: `b = [-3, 4, 2, -1, 1, 0]`, правильный ответ
`a = [1, 1, 3, 2, 6, 3]`.

Здесь `a1 = 1` — это значение `b`, равное `1`, взятое "как есть" в роли `a1`.
Оставшиеся значения `{-3, 4, 2, -1, 0}` расставлены как разности в порядке
`d2=0, d3=2, d4=-1, d5=4, d6=-3` (проверка: `1+0=1`, `1+2=3`, `3-1=2`,
`2+4=6`, `6-3=3` — совпадает с `a`).

Теперь соберём это в единую перестановку `c`:

```
c = (1, 0, 2, -1, 4, -3)
```

Это перестановка всех 6 элементов `b` (все значения `-3,4,2,-1,1,0`
присутствуют, каждое по одному разу). А её префиксные суммы:

```
c1       = 1
c1+c2    = 1
c1+c2+c3 = 3
...      = 2
...      = 6
...      = 3
```

то есть `(1, 1, 3, 2, 6, 3)` — это в точности `a`. Никакого отдельного
"выбора `a1`" в этом расчёте не потребовалось — он "встроен" в то, что первая
префиксная сумма состоит из одного слагаемого.

### Итоговая переформулировка

Раз любой способ восстановить `a` из `b` (выбор роли `a1` + порядок разностей)
однозначно соответствует некоторой перестановке всего мультимножества `b`, и
наоборот — любая перестановка `b` даёт корректный (по построению) вариант
восстановления, — задачи полностью эквивалентны:

> Переставить мультимножество `b` так, чтобы все префиксные суммы были строго
> положительны, а последовательность префиксных сумм была лексикографически
> наименьшей.

А раз `a_i` — это просто `i`-я префиксная сумма перестановки, "лексикографически
наименьший `a`" и "лексикографически наименьшая последовательность префиксных
сумм" — это буквально одно и то же требование, а не два разных.

## Почему достаточно локальной жадности

Пусть на каком-то шаге уже накоплена сумма `S > 0`, а оставшееся мультимножество
элементов — `R`. Нужно решить, какой элемент `x ∈ R` взять следующим.

Обязательное условие — `S + x > 0` (иначе `a_i` не будет положительным).

Вопрос: если это условие выполнено, всегда ли можно **корректно расставить**
оставшиеся элементы `R \ {x}` так, чтобы дальнейшие префиксные суммы тоже
остались положительными?

Ответ — да, и вот почему. Рассмотрим "безопасный" порядок расстановки любого
набора `R`: сначала все неотрицательные элементы (в любом порядке), потом все
отрицательные — от наименьшего по модулю к наибольшему по модулю. Тогда:

- Пока идут неотрицательные — сумма только растёт, значит остаётся `≥ S > 0`.
- Пока идут отрицательные — сумма **монотонно убывает** к своему финальному
  значению (каждый следующий элемент тоже отрицателен). Значит, минимум на
  этом участке достигается в самом конце, то есть равен итоговой сумме после
  добавления всех элементов `R`.

Итоговая сумма после добавления всех элементов `R` — это просто `S + sum(R)`,
то есть **сумма всех элементов `b`** (она не зависит от выбранного порядка!
Она равна финальному `a_n`). А значит, если исходно `sum(b) > 0`, то при
безопасном порядке все промежуточные суммы гарантированно положительны — вне
зависимости от того, какой именно элемент `x` был выбран на текущем шаге.

**Вывод:** пока `sum(b) > 0`, единственное реальное ограничение на каждом шаге —
локальное (`S + x > 0`). Значит, чтобы получить лексикографически наименьший
результат, достаточно на каждом шаге брать **наименьший** элемент из
оставшихся, который не нарушает `S + x > 0`. Никакого перебора или проверки
"а не сломает ли это будущее" не требуется — она всегда пройдёт успешно.

## Алгоритм

1. Если `sum(b) < 1` — ответ `-1` (последний элемент `a_n` всегда равен сумме
   `b`, а он обязан быть положительным).
2. Отсортировать `b` по возрастанию.
3. Поддерживать текущую сумму `S = 0` и структуру "оставшиеся элементы",
   позволяющую быстро находить наименьший ещё не использованный элемент,
   который больше `-S`.
4. На каждом из `n` шагов: найти такой элемент, прибавить к `S`, записать `S`
   как очередное `a_i`, пометить элемент использованным.

### Быстрый поиск "наименьший неиспользованный элемент, больший порога"

Так как элементы только удаляются (никогда не добавляются обратно), для этого
используется классический приём — система непересекающихся множеств (DSU) поверх
отсортированного массива:

- `find(i)` возвращает индекс ближайшего **неиспользованного** элемента с
  индексом `≥ i`.
- Индекс, откуда нужно начинать поиск, находится бинарным поиском
  (`sort.Search`) — первая позиция, где значение больше порога.
- После использования элемента с индексом `idx` делаем `parent[idx] = idx + 1`
  — DSU "перепрыгивает" через него при следующих запросах.

Каждый элемент удаляется (объединяется) не более одного раза, поэтому суммарная
сложность — `O(n log n)` (бинарный поиск) с почти константным `amortized`-временем
на операции DSU.

## Сложность

- Время: `O(n log n)` на тест, `O(ΣN log ΣN)` суммарно.
- Память: `O(n)`.

## Пример разбора

`b = [-3, 4, 2, -1, 1, 0]`, `sum(b) = 3 > 0`.

Отсортировано: `[-3, -1, 0, 1, 2, 4]`.

| Шаг | S до | Порог (`> -S`) | Выбранный элемент | S после |
|-----|------|-----------------|--------------------|---------|
| 1   | 0    | `> 0`           | 1                  | 1       |
| 2   | 1    | `> -1`          | 0                  | 1       |
| 3   | 1    | `> -1`          | 2                  | 3       |
| 4   | 3    | `> -3`          | -1                 | 2       |
| 5   | 2    | `> -2`          | 4                  | 6       |
| 6   | 6    | `> -6`          | -3                 | 3       |

Результат: `a = [1, 1, 3, 2, 6, 3]` — совпадает с примером из условия.

## История багфикса

Изначальная реализация строила массив «с конца», выбирая на каждом шаге между
наименьшим и наибольшим из оставшихся элементов `b` (жадность по
двум указателям). Этот подход внешне похож на правильный и проходит
пример из условия, но не эквивалентен настоящей лексикографической
минимизации: на входе `b = [1, 2, 0, -1, -2, 2]` он выдавал `1 1 3 2 4 2`,
а верный ответ — `1 1 3 1 3 2`. Ошибка была найдена стресс-тестом со
сравнением против полного перебора на малых `n`. После переосмысления задачи
как "префиксные суммы перестановки `b`" и доказательства, что локальной
жадности достаточно, решение было переписано (см. `main.go`).
